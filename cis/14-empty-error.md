## 14. 空與錯 Empty & Error

設計原則總綱:**靜默失敗是最大病原。** 空要說「東西什麼時候會來」,
錯要**留痕**(原始錯誤訊息不吞)且**可重試**;任何破壞性結果給 5 秒後悔窗。

### 14.1 空狀態公式

空狀態三件套(iOS 用系統 `ContentUnavailableView`,他端等效結構):

```
      〔icon〕
   人話標題               ← 一句陳述現狀:「沒有 X」「尚無 X」「還沒看到 X」,不用技術詞
   副標:X 會出現在這裡    ← + 一句「下一步 / 觸發條件」(東西什麼時候會來、怎麼讓它來)
   〔CTA〕                ← 有下一步可做才給(一顆 prominent 鈕);純等待型不給
```

| 件 | 規則 |
|---|---|
| 標題 | 人話陳述現狀,不用技術詞 |
| 副標 | 「X 會出現在這裡」+ 下一步或觸發條件(讓人知道這不是壞掉,是還沒來) |
| CTA | 有可做的下一步才出現(例:掃描 QR 配對);純等待型(錯誤記錄、子程序)不給 |
| icon | 正向空 = `checkmark.seal`;無項 = `person.2.slash`/`tray` 類;實體缺 = 對應物件 symbol |

出貨實例(抄自現行文案,供語感校準):

- 「沒有錯誤記錄」+「發生錯誤時會自動記在這裡,並同步到後端供檢查。」(icon `checkmark.seal`,無 CTA)
- 「還沒看到你的 Mac」+「…約一分鐘內會出現在這裡。也可以直接掃描桌面的配對 QR。」+ CTA「掃描 QR 配對」
- 「此 session 尚無子程序」+「從這條 session 派出的子程序會出現在這裡;可點進去看即時狀態、隨時中斷或收工。」

### 14.2 搜尋無結果三件套

搜尋空態不只丟「沒有結果」讓人猜 —— 要**交代搜了哪裡、給收斂建議、附一鍵清除**:

| 件 | 規格 |
|---|---|
| icon + 標題 | `magnifyingglass` + 「沒有符合的結果」 |
| 副標 | 「已搜尋〔範圍人話〕,找不到「〔原查詢字〕」。試試更短的關鍵字,或拆開詞彙再搜。」 |
| CTA | 「清除搜尋」—— 清空查詢字,清單立即復原 |

範圍(scope)由呼叫端用人話傳入,例:「歷史 session 的標題與專案」。

### 14.3 錯誤要留痕、要說話(loadError 範式)

內容頁三態:**loading / error / 內容**。error 態規格:

```
      〔wifi.exclamationmark〕          ← 連線類錯誤統一此 icon
   「X 暫時無法取得」                    ← 標題句式固定
   原始錯誤訊息(errorText 原文)          ← 留痕:不改寫成通用句、不吞
   〔重試〕                             ← bordered 鈕,動作 = 重跑 load
```

- **留痕鐵則**:description 直接吐原始錯誤文字。通用句(「發生錯誤」)是禁例 ——
  除錯靠這行字。
- 清單內的 inline 同步失敗用輕量款:`arrow.clockwise` icon + 「最新訊息尚未同步,重試」
  一列鈕,不打斷清單。
- 錯誤同時寫入錯誤記錄頁(可回看、同步後端)—— UI 留痕 + 日誌留痕雙軌。
- 失敗標記淡化處理:列表上的 failed 態用 phase 表的 danger 色 symbol,
  不做整列刺眼紅底(「紅是訊號不是地毯」同款紀律)。

### 14.4 Undo 範式(5 秒聚合)

破壞性/收起類操作(結案、擱置、封存、刪除)不擋確認框,改走 **做掉 + 5 秒後悔窗**:

| 項 | 規格 |
|---|---|
| 後悔窗 | **5 秒**(每次新操作進來重置) |
| 聚合鍵 | 操作種類(kind,如 `session.settle`);同類連做 → 計數聚合成一條 |
| 換類 | 上一條直接過期(動作已生效,只放棄後悔窗),新類重新計數 |
| 文案 | 單筆:「已結案「〔標題〕」」;聚合:「已結案 N 個」(已擱置同款) |
| 復原 | 「復原」鈕一次退全部,**LIFO**(後做先退,列表順序才回得去) |
| 視覺 | 底部 snackbar:黑 @82% 底、圓角 20、影級 3(lg)、白 caption 字、「復原」字 warning 色;底部讓開浮動頁籤(bottom padding 72) |
| 進出場 | 由下滑入 + 淡入;slow 檔動畫 |

**自動結案必走 Undo**:閒置自動收起不得無聲消失 —— 收起時列表頂部給提示列
「已自動收起 N 個閒置會話 · 查看」(見 [13-state-language.md](13-state-language.md) §13.6)。

### 14.5 Skeleton(量化呼吸,非 shimmer)

骨架屏與 Working 訊號分工:**shimmer 掃字屬「進行中」語彙,skeleton 呼吸屬「載入中」語彙**,不混用。

| 參數 | 值 |
|---|---|
| 型態 | 整塊 opacity 呼吸,**量化步進 steps(4)**,無連續補間(GPU 近零負擔) |
| 步值 | opacity `1.0 → 0.82 → 0.64 → 0.82`(循環) |
| 步長 | 0.35s/格,一輪 **1.4s** |
| 視窗外 | 滾出視窗即停在 opacity 1.0,不空轉 |
| reduced-motion | 不播,直接出靜態骨架 |

web 對位:`steps(4)` 的 CSS animation 同參數(歸納自現行 iOS 實作的對位)。

### 14.6 破壞性確認(真要確認的那種)

無法 Undo 的操作(刪除會話、登出解配、清對話)才用確認對話框,且**講清楚失去什麼**:
標題 = 動作本身;內文 = 具體後果(刪掉幾筆、是否可復原);確認鈕 = 動詞
(「刪除」不是「確定」),destructive 紅。詳見 [15-voice-tone.md](15-voice-tone.md) §15.4。
